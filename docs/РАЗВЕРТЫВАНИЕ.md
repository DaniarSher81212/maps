**Версия:** 3.1.0 | **Дата:** 2026-05-31

## Быстрая установка на сервер (одна команда)

Скопируйте проект на сервер и запустите:

```bash
sudo bash deploy/server_install.sh
```

Скрипт задаст три вопроса (порт, пароль, нужен ли Nginx) и сделает всё остальное сам:
установит Docker, поднимет PostgreSQL и MAPS в контейнерах, настроит автозапуск при перезагрузке.

**Без вопросов (для автоматизации):**
```bash
sudo bash deploy/server_install.sh --port 8000 --password МойПароль --nginx --silent
```

> Если нужно передать скрипт в IT-отдел — см. раздел «Передача в IT-отдел» в конце этого документа.

## 1. Выбор варианта развёртывания

| Вариант | Когда использовать | Сложность | Рекомендуется |
|---|---|---|---|
| **Локальный** | Тестирование, разработка | Низкая | Разработчику |
| **Linux Ubuntu/Debian** | Корпоративный сервер на Ubuntu | Средняя | ✅ Основной вариант |
| **Linux RHEL/CentOS** | Корпоративный сервер на RHEL | Средняя | Если в компании RHEL |
| **Docker Compose** | Любая ОС, изолированная среда | Низкая | ✅ Если есть Docker |
| **Windows Server** | Когда Linux недоступен | Высокая | Запасной вариант |
| **Облако** | Публичный доступ через интернет | Средняя | Если нет своего сервера |

**Требования для всех вариантов:**
- PostgreSQL 15+ (или корпоративный сервер PostgreSQL)
- Python 3.11+ (кроме Docker — Python внутри контейнера)
- 1 ГБ RAM минимум, 2 ГБ рекомендуется
- 5 ГБ дискового пространства

## 2. Вариант 1 — Локальный запуск

### На Windows

**Шаг 1. Установить PostgreSQL**

Скачать с сайта postgresql.org → установить с настройками по умолчанию.
Запомнить пароль суперпользователя `postgres`.

После установки открыть pgAdmin или psql и создать базу:
```sql
CREATE USER maps_user WITH PASSWORD 'ваш_пароль';
CREATE DATABASE maps_db OWNER maps_user;
GRANT ALL PRIVILEGES ON DATABASE maps_db TO maps_user;
```

**Шаг 2. Установить Python 3.11+**

Скачать с python.org. При установке поставить галочку «Add Python to PATH».

Проверка:
```cmd
python --version
```

**Шаг 3. Скопировать проект**

```cmd
git clone https://github.com/DaniarSher81212/maps.git
cd maps
```

Или распаковать ZIP-архив из GitHub.

**Шаг 4. Создать виртуальное окружение**

```cmd
python -m venv .venv
.venv\Scripts\activate
pip install -e .
```

**Шаг 5. Создать файл .env**

Создать файл `.env` в корне проекта:
```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=maps_db
DB_USER=maps_user
DB_PASSWORD=ваш_пароль
APP_ENV=development
LOG_LEVEL=INFO
SESSION_PREFIX=session
DATA_DIR=data
EXPORT_DIR=data/exports
```

**Шаг 6. Создать таблицы**

```cmd
alembic upgrade head
```

**Шаг 7. Запустить**

```cmd
python -m uvicorn app.api.main:app --host 0.0.0.0 --port 8000 --reload
```

Открыть в браузере: http://localhost:8000

## 3. Вариант 2 — Linux-сервер Ubuntu/Debian

Это основной рекомендуемый вариант для корпоративного развёртывания.
MAPS запускается как systemd-сервис и стартует автоматически при перезагрузке сервера.

### Быстрая установка (автоматически)

Если на сервере есть интернет и git:

```bash
# Подключиться к серверу по SSH
ssh ubuntu@ВАШ_СЕРВЕР

# Скачать проект
git clone https://github.com/DaniarSher81212/maps.git
cd maps

# Запустить скрипт установки
sudo bash deploy/setup.sh
```

Скрипт сделает всё автоматически за 3–5 минут. После завершения:

```bash
# Запустить MAPS
sudo systemctl start maps

# Проверить что работает
sudo systemctl status maps
curl http://localhost:8000/api/status
```

---

### Ручная установка (пошагово)

Используйте этот способ если:
- Нет доступа к интернету
- Нужен полный контроль над каждым шагом
- Автоматический скрипт не подходит

**Шаг 1. Установить системные зависимости**

```bash
sudo apt-get update
sudo apt-get install -y \
    python3.11 \
    python3.11-venv \
    python3.11-dev \
    python3-pip \
    postgresql \
    postgresql-contrib \
    libpq-dev \
    git \
    build-essential \
    curl
```

**Шаг 2. Настроить PostgreSQL**

```bash
# Запустить PostgreSQL
sudo systemctl start postgresql
sudo systemctl enable postgresql

# Создать пользователя и базу
sudo -u postgres psql -c "CREATE USER maps_user WITH PASSWORD 'ЗАМЕНИТЕ_НА_СВОЙ_ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE maps_db OWNER maps_user;"
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE maps_db TO maps_user;"
```

**Шаг 3. Скопировать проект**

```bash
# Вариант A — через Git (если есть доступ к GitHub)
git clone https://github.com/DaniarSher81212/maps.git ~/maps

# Вариант B — через SCP с локальной машины (без интернета на сервере)
# Выполнять на ЛОКАЛЬНОЙ машине:
scp -r /путь/к/maps ubuntu@ВАШ_СЕРВЕР:~/maps
```

**Шаг 4. Создать виртуальное окружение**

```bash
cd ~/maps
python3.11 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -e .
```

Если нет интернета (offline установка):

```bash
# На машине с интернетом — скачать все пакеты
pip download -r requirements.txt -d /tmp/maps-packages

# Скопировать пакеты на сервер (SCP или USB)
scp -r /tmp/maps-packages ubuntu@СЕРВЕР:/tmp/

# На сервере — установить из локального кэша
.venv/bin/pip install --no-index --find-links /tmp/maps-packages -e .
```

**Шаг 5. Создать .env файл**

```bash
cat > ~/maps/.env << 'EOF'
DB_HOST=localhost
DB_PORT=5432
DB_NAME=maps_db
DB_USER=maps_user
DB_PASSWORD=ЗАМЕНИТЕ_НА_СВОЙ_ПАРОЛЬ

APP_ENV=production
LOG_LEVEL=INFO
SESSION_PREFIX=session
DATA_DIR=/home/ubuntu/maps/data
EXPORT_DIR=/home/ubuntu/maps/data/exports
EOF

chmod 600 ~/maps/.env   # Только владелец может читать (там пароль!)
```

**Шаг 6. Создать директории и таблицы**

```bash
mkdir -p ~/maps/data/exports ~/maps/logs

cd ~/maps
.venv/bin/alembic upgrade head
```

**Шаг 7. Зарегистрировать как systemd-сервис**

Создать файл `/etc/systemd/system/maps.service`:

```bash
sudo tee /etc/systemd/system/maps.service << 'EOF'
[Unit]
Description=MAPS — Material Allocation & Planning System
After=network.target
After=postgresql.service
Requires=postgresql.service

[Service]
Type=simple
User=ubuntu
Group=ubuntu
WorkingDirectory=/home/ubuntu/maps
EnvironmentFile=/home/ubuntu/maps/.env
ExecStart=/home/ubuntu/maps/.venv/bin/uvicorn app.api.main:app \
    --host 0.0.0.0 \
    --port 8000 \
    --log-level info
Restart=on-failure
RestartSec=5s
StandardOutput=journal
StandardError=journal
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
EOF
```

> **Важно:** замените `ubuntu` на имя вашего пользователя, `/home/ubuntu/maps` на реальный путь к проекту.

```bash
sudo systemctl daemon-reload
sudo systemctl enable maps    # Автозапуск при перезагрузке
sudo systemctl start maps

# Проверка
sudo systemctl status maps
```

**Шаг 8. Настроить файрвол**

```bash
# Если пользователи подключаются напрямую по порту 8000:
sudo ufw allow 8000/tcp
sudo ufw reload

# Если через Nginx (рекомендуется) — открыть только 80/443:
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw reload
```

## 4. Вариант 3 — Linux-сервер RHEL/CentOS/Rocky Linux

### Отличия от Ubuntu

На RHEL-совместимых системах используйте `dnf` вместо `apt-get`:

```bash
# Шаг 1. Зависимости
sudo dnf install -y \
    python3.11 \
    python3.11-devel \
    postgresql-server \
    postgresql-contrib \
    postgresql-devel \
    gcc \
    git \
    curl

# Шаг 2. PostgreSQL (инициализация отличается от Ubuntu!)
sudo postgresql-setup --initdb
sudo systemctl start postgresql
sudo systemctl enable postgresql

# Шаг 3. Разрешить аутентификацию по паролю
# В RHEL PostgreSQL по умолчанию использует ident-аутентификацию.
# Нужно изменить это для maps_user.
sudo nano /var/lib/pgsql/data/pg_hba.conf
# Найти строку:
#   host    all             all             127.0.0.1/32            ident
# Заменить на:
#   host    all             all             127.0.0.1/32            md5

sudo systemctl restart postgresql
```

Далее — те же шаги 2–8 из Варианта 2, но пути могут отличаться:
- Пользователь: `ec2-user` или `rocky` вместо `ubuntu`
- Python может быть как `python3.11`, так и `python3`

## 5. Вариант 4 — Docker Compose

Это самый переносимый вариант: работает на любой ОС где есть Docker.
PostgreSQL и MAPS запускаются вместе в изолированных контейнерах.

### Предварительные требования

```bash
# Установить Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # Добавить себя в группу docker
# Перезайти в систему чтобы изменения применились

# Проверить установку
docker --version
docker compose version
```

### Запуск

```bash
# Скачать проект
git clone https://github.com/DaniarSher81212/maps.git
cd maps

# Создать .env для Docker (с хостом postgres вместо localhost)
cat > .env.docker << 'EOF'
DB_HOST=postgres
DB_PORT=5432
DB_NAME=maps_db
DB_USER=maps_user
DB_PASSWORD=ЗАМЕНИТЕ_НА_СВОЙ_ПАРОЛЬ
APP_ENV=production
LOG_LEVEL=INFO
SESSION_PREFIX=session
DATA_DIR=/app/data
EXPORT_DIR=/app/data/exports
EOF

# Запустить
docker compose up -d

# Проверить
docker compose ps
curl http://localhost:8000/api/status
```

Открыть в браузере: http://localhost:8000

### Управление Docker

```bash
# Просмотр логов
docker compose logs -f maps
docker compose logs -f postgres

# Остановить
docker compose down

# Остановить и удалить базу данных (ОСТОРОЖНО — все данные удалятся!)
docker compose down -v

# Перезапустить после обновления кода
docker compose build maps
docker compose up -d maps

# Войти в контейнер для диагностики
docker compose exec maps bash
docker compose exec postgres psql -U maps_user -d maps_db
```

### Если PostgreSQL уже есть (только MAPS в Docker)

Если у вас уже есть корпоративный PostgreSQL, запустите только MAPS:

```bash
# .env с адресом корпоративного PostgreSQL
cat > .env << 'EOF'
DB_HOST=адрес_вашего_postgresql
DB_PORT=5432
DB_NAME=maps_db
DB_USER=maps_user
DB_PASSWORD=пароль
APP_ENV=production
LOG_LEVEL=INFO
SESSION_PREFIX=session
DATA_DIR=/app/data
EXPORT_DIR=/app/data/exports
EOF

# Запустить только MAPS (без встроенного PostgreSQL)
docker compose -f docker-compose.yml up -d maps
```

1. **Python 3.11+** — скачать с python.org, установить с «Add to PATH»
2. **PostgreSQL 15+** — скачать с postgresql.org
3. **Git** — скачать с git-scm.com (опционально)

### Установка

**Шаг 1. Создать базу данных**

Открыть pgAdmin или psql и выполнить:
```sql
CREATE USER maps_user WITH PASSWORD 'ваш_пароль';

**Шаг 2. Скопировать проект**

```

Или распаковать вручную в `C:\maps`.

**Шаг 3. Установить зависимости**

```cmd
python -m venv .venv
.venv\Scripts\activate
pip install -e .
```

**Шаг 4. Создать .env**

Создать файл `C:\maps\.env` с содержимым:
```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=maps_db
DB_USER=maps_user
DB_PASSWORD=ваш_пароль
APP_ENV=production
LOG_LEVEL=INFO
SESSION_PREFIX=session
DATA_DIR=C:\maps\data
EXPORT_DIR=C:\maps\data\exports
```

**Шаг 5. Создать таблицы**

```cmd
cd C:\maps
.venv\Scripts\alembic upgrade head
```

**Шаг 6. Проверить запуск вручную**

```cmd
.venv\Scripts\uvicorn app.api.main:app --host 0.0.0.0 --port 8000
```

Открыть http://localhost:8000 — должен работать.

**Шаг 7. Установить как Windows-сервис через NSSM**

NSSM (Non-Sucking Service Manager) позволяет запустить любую программу как службу Windows.

```cmd
# Скачать NSSM: https://nssm.cc/download
# Распаковать nssm.exe в C:\tools\nssm.exe

# Установить сервис
C:\tools\nssm.exe install MAPS "C:\maps\.venv\Scripts\uvicorn.exe"
C:\tools\nssm.exe set MAPS AppParameters "app.api.main:app --host 0.0.0.0 --port 8000"
C:\tools\nssm.exe set MAPS AppDirectory "C:\maps"
C:\tools\nssm.exe set MAPS AppEnvironmentExtra "DB_HOST=localhost" "DB_PORT=5432" "DB_NAME=maps_db" "DB_USER=maps_user" "DB_PASSWORD=ваш_пароль" "APP_ENV=production" "LOG_LEVEL=INFO" "SESSION_PREFIX=session" "DATA_DIR=C:\maps\data" "EXPORT_DIR=C:\maps\data\exports"
C:\tools\nssm.exe set MAPS Start SERVICE_AUTO_START

# Запустить
C:\tools\nssm.exe start MAPS
```

Управление сервисом:
```cmd
C:\tools\nssm.exe start MAPS     # Запустить
C:\tools\nssm.exe stop MAPS      # Остановить
C:\tools\nssm.exe restart MAPS   # Перезапустить
C:\tools\nssm.exe status MAPS    # Статус
C:\tools\nssm.exe remove MAPS    # Удалить сервис
```

Или через стандартный диспетчер служб Windows: `services.msc` → найти «MAPS».

## 8. Варианты доступа пользователей

После того как MAPS запущен, нужно дать пользователям доступ к нему.

### Вариант A — Прямой доступ по IP:порт

Самый простой. Пользователи открывают в браузере:
```
http://192.168.1.100:8000
```

Подходит для: внутренней сети, тестирования.

Недостаток: порт 8000 нестандартный, некоторые корпоративные файрволы его блокируют.

**Что нужно:**
- Открыть порт 8000 в файрволе сервера (см. выше `ufw allow 8000/tcp`)
- Убедиться что корпоративный файрвол пропускает этот порт

---

### Вариант B — Nginx reverse proxy (рекомендуется для production)

Nginx принимает запросы на стандартный порт 80 (или 443 для HTTPS) и перенаправляет их на MAPS (порт 8000). Пользователи открывают:
```
http://maps.ваш-домен.ru
```

**Установка Nginx:**

```bash
sudo apt-get install -y nginx
```

**Конфигурация `/etc/nginx/sites-available/maps`:**

```nginx
server {
    listen 80;
    server_name maps.ваш-домен.ru;   # или IP-адрес сервера

    # Максимальный размер загружаемых файлов (Excel-файлы могут быть большими)
    client_max_body_size 50M;

    # Таймаут для длинных запросов (расчёт может занимать несколько минут)
    proxy_read_timeout 300s;
    proxy_connect_timeout 10s;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

```bash
# Включить сайт
sudo ln -s /etc/nginx/sites-available/maps /etc/nginx/sites-enabled/
sudo nginx -t          # Проверить конфигурацию
sudo systemctl reload nginx

# Открыть порт 80
sudo ufw allow 80/tcp
sudo ufw reload
```

**Добавить HTTPS с Let's Encrypt (если сервер доступен из интернета):**

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d maps.ваш-домен.ru
# Certbot сам добавит HTTPS в конфиг Nginx
```

**Для корпоративного сервера без публичного интернета** используйте самоподписанный сертификат или корпоративный CA.

---

### Вариант C — Cloudflare Tunnel (без открытия портов)

Позволяет дать публичный HTTPS-доступ к серверу не открывая никаких портов в файрволе. Cloudflare создаёт защищённый туннель между вашим сервером и своей CDN.

```bash
# Временный туннель (URL меняется после перезапуска)
bash deploy/tunnel.sh

# Фоновый запуск
bash deploy/tunnel.sh --bg
cat /tmp/maps_tunnel.url
```

Подходит для: быстрого доступа, демонстраций, когда нельзя открыть порты.

Не подходит для: постоянного продакшена (URL меняется при перезапуске).

Для постоянного туннеля нужно зарегистрировать аккаунт Cloudflare и настроить именованный туннель — см. документацию Cloudflare Zero Trust.

## 9. Подключение к корпоративной PostgreSQL

Если в компании уже есть PostgreSQL-сервер (или ваш DBA дал вам подключение), не нужно устанавливать PostgreSQL отдельно.

**Что нужно от DBA (администратора БД):**

1. Адрес сервера PostgreSQL (hostname или IP)
2. Порт (обычно 5432)
3. Имя пользователя и пароль с правами `CREATE TABLE` и `SELECT/INSERT/UPDATE/DELETE`
4. Имя базы данных (или право создать новую)

**Пример .env для корпоративного PostgreSQL:**

```env
DB_HOST=pg.corp.company.ru
DB_PORT=5432
DB_NAME=maps_db
DB_USER=maps_app_user
DB_PASSWORD=пароль_от_dba
APP_ENV=production
LOG_LEVEL=INFO
SESSION_PREFIX=session
DATA_DIR=/home/ubuntu/maps/data
EXPORT_DIR=/home/ubuntu/maps/data/exports
```

**Проверить подключение:**

```bash
# Из командной строки
psql -h pg.corp.company.ru -U maps_app_user -d maps_db -c "SELECT version();"

# Или через Python
python3 -c "
import psycopg2
conn = psycopg2.connect(host='pg.corp.company.ru', port=5432, 
                        dbname='maps_db', user='maps_app_user', 
                        password='пароль')
print('Подключение успешно:', conn.server_version)
conn.close()
"
```

**Создать таблицы в корпоративной БД:**

```bash
cd ~/maps
.venv/bin/alembic upgrade head
```

## 13. Диагностика проблем

### MAPS не запускается

```bash
# Посмотреть логи
sudo journalctl -u maps -n 50 --no-pager

# Частые причины:
# 1. PostgreSQL не запущен
sudo systemctl status postgresql

# 2. Неверный пароль в .env
cat ~/maps/.env | grep DB_PASSWORD
psql -h localhost -U maps_user -d maps_db -c "SELECT 1;"   # Проверить вручную

# 3. Порт 8000 занят другим процессом
sudo lsof -i :8000
sudo fuser -k 8000/tcp   # Освободить порт
```

### API возвращает 500

```bash
# Смотреть подробные логи
sudo journalctl -u maps -f

# Включить режим DEBUG в .env
LOG_LEVEL=DEBUG
sudo systemctl restart maps
```

### Ошибка "relation does not exist"

Значит миграции не были применены:

```bash
cd ~/maps
.venv/bin/alembic upgrade head
sudo systemctl restart maps
```

### Не работает Docker

```bash
# Посмотреть логи контейнера
docker compose logs maps
docker compose logs postgres

# PostgreSQL не успел запуститься до MAPS
# Подождать 10 секунд и перезапустить MAPS
docker compose restart maps

# Пересоздать всё с нуля (УДАЛИТ ДАННЫЕ!)
docker compose down -v
docker compose up -d
```

### Файрвол блокирует подключения

```bash
# Проверить что порт открыт
sudo ufw status
sudo ss -tlnp | grep 8000

# Проверить что MAPS слушает на 0.0.0.0 (а не только на 127.0.0.1)
sudo ss -tlnp | grep 8000
# Должно быть: 0.0.0.0:8000 (не 127.0.0.1:8000)
```

### Большие Excel-файлы не загружаются

FastAPI по умолчанию принимает файлы до 100 МБ. Если файл больше или Nginx возвращает 413:

```bash
# В конфиге Nginx увеличить лимит
client_max_body_size 200M;
sudo systemctl reload nginx
```
