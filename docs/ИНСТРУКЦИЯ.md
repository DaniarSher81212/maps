## 1. Как устроена система

```
Ваш компьютер                    Oracle Cloud сервер (132.145.232.46)
──────────────                   ──────────────────────────────────────
Браузер ──────── туннель ──────► MAPS (порт 8000)
                                      │
Excel-файлы ──► дашборд ──────────────┘
                                      │
                                 PostgreSQL (БД)
                                      │
                                 Claude API (AI-функции)
```

**Что делает MAPS:**
- Принимает Excel-файлы с потребностями работ и остатками склада
- Автоматически распределяет материалы по 5 слоям (списания → склад → поставки → дефицит)
- Аварийные работы всегда получают материалы первыми
- Выдаёт Excel-отчёт с полным разбором

**Что такое туннель:**  
Cloudflare создаёт временную публичную ссылку вида `https://xxxx.trycloudflare.com`.
Через неё можно открыть MAPS с любого компьютера в интернете, не открывая порты.
URL меняется при каждом перезапуске туннеля.

## 2. Запуск на локальном компьютере

Используется для разработки и тестирования. Не нужен сервер.

### 2.1 Первый запуск (один раз)

```bash
# Перейти в папку проекта
cd ~/dev/projects/python/PythonProject

# Активировать виртуальное окружение
# Виртуальное окружение — это изолированная папка с Python и всеми пакетами проекта.
# Без него пакеты могут конфликтовать с другими проектами на компьютере.
source .venv/bin/activate

# Убедиться что .env настроен (должен быть файл с настройками БД)
cat .env
```

Минимальный `.env` для локального запуска:
```
DB_HOST=localhost
DB_PORT=5432
DB_NAME=maps_db
DB_USER=maps_user
DB_PASSWORD=ваш_пароль
ANTHROPIC_API_KEY=sk-ant-api03-...
```

### 2.2 Запуск сервера

```bash
# Из папки проекта с активированным .venv:
.venv/bin/uvicorn app.api.main:app --reload --port 8000
```

Флаг `--reload` означает: при изменении кода сервер перезапускается автоматически.
Удобно для разработки, не нужен на сервере.

После запуска вы увидите:
```
INFO:     Started server process [12345]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000
```

Откройте в браузере: **http://localhost:8000**

### 2.3 Остановить сервер

Нажмите **Ctrl+C** в терминале где запущен uvicorn.

### 2.4 Если порт уже занят

Ошибка: `ERROR: [Errno 98] address already in use`

```bash
# Найти и убить процесс на порту 8000
sudo fuser -k 8000/tcp

# После этого снова запустить сервер
.venv/bin/uvicorn app.api.main:app --reload --port 8000
```

## 3. Работа с сервером Oracle Cloud

Сервер работает постоянно. MAPS запускается автоматически при включении сервера.

**Данные сервера:**
- IP-адрес: `132.145.232.46`
- Пользователь: `ubuntu`
- SSH-ключ (локальный компьютер): `/home/dan/keys/oracle.pem`
- SSH-алиас: `maps-server` (настроен в `~/.ssh/config`)
- Дашборд (прямой доступ): `http://132.145.232.46:8000`

---

### 3.1 Вариант А — Прямой доступ через браузер (самый простой)

Порт 8000 открыт напрямую в интернет. Никаких туннелей не нужно.

**Просто откройте в браузере:**
```
http://132.145.232.46:8000
```

Этот адрес **постоянный** — он не меняется никогда. Работает из любой сети: домашней, мобильной, офисной.

**Когда прямой доступ не работает:**

| Симптом | Причина | Решение |
|---------|---------|---------|
| Браузер показывает «Сайт недоступен» | MAPS не запущен | Подключиться по SSH и выполнить `sudo systemctl start maps` |
| Страница грузится бесконечно | Файрвол Oracle закрыл порт | Войти в Oracle Cloud Console → VCN → Security Lists → добавить правило для порта 8000 |
| Страница открывается, но показывает ошибку 502 | MAPS упал после старта | Проверить логи: `sudo journalctl -u maps -n 30 --no-pager` |

> **Ограничение:** адрес начинается с `http://` (без S) — соединение не зашифровано.
> Для публичного использования или передачи чувствительных данных лучше использовать
> туннель Cloudflare (Вариант Б), который автоматически даёт `https://`.

### 3.2 Вариант Б — Cloudflare туннель (для корпоративных сетей)

Некоторые корпоративные сети блокируют прямые подключения к нестандартным портам (8000).
Cloudflare туннель обходит это ограничение: трафик идёт через серверы Cloudflare по стандартному порту 443 (HTTPS).

#### Как это работает

```
Ваш браузер  →  Cloudflare (серверы в интернете)  →  cloudflared на сервере  →  MAPS :8000
```

Программа `cloudflared` на сервере сама «прорывает» исходящее соединение к Cloudflare.
Никаких изменений в файрволе не нужно — соединение идёт изнутри наружу.

#### Текущий статус туннеля

Туннель настроен как systemd-сервис `cloudflared-maps` и запускается автоматически вместе с сервером.

```bash
# Проверить работает ли туннель
sudo systemctl status cloudflared-maps

# Посмотреть текущий URL туннеля
sudo journalctl -u cloudflared-maps --no-pager | grep trycloudflare.com | tail -1
```

Пример вывода:
```
May 30 09:08:22 ... |  https://wallpapers-glance-lexmark-nhs.trycloudflare.com  |
```

> **Важно:** При каждом перезапуске сервера или сервиса URL **меняется** — это особенность
> бесплатного режима trycloudflare. Для постоянного URL см. Вариант В.

#### Управление туннелем

```bash
# Запустить туннель (если остановлен)
sudo systemctl start cloudflared-maps

# Остановить туннель
sudo systemctl stop cloudflared-maps

# Перезапустить (получить новый URL)
sudo systemctl restart cloudflared-maps

# Включить автозапуск при старте сервера (уже включён)
sudo systemctl enable cloudflared-maps

# Отключить автозапуск
sudo systemctl disable cloudflared-maps
```

#### Получить актуальный URL после перезапуска

```bash
# Способ 1 — из журнала systemd
sudo journalctl -u cloudflared-maps --no-pager | grep 'trycloudflare.com' | tail -1

# Способ 2 — из метрик cloudflared (машинно-читаемый формат)
curl -s http://127.0.0.1:20241/metrics | grep 'userHostname'
```

#### Типичные ошибки туннеля

**Ошибка: Cloudflare Error 1033 — «Tunnel error»**

```
Error 1033 Ray ID: ...
cloudflared is currently unable to resolve it
```

Причина: туннель только запустился, Cloudflare ещё не распространил маршрут (занимает 10–30 секунд).

Решение:
```bash
# Проверить что туннель реально подключился
sudo journalctl -u cloudflared-maps -n 5 --no-pager | grep -E 'Registered|error'
# Должна быть строка: "Registered tunnel connection ... protocol=quic"

# Подождать 30 секунд и обновить страницу в браузере
```

---

**Ошибка: страница не открывается, браузер показывает «ERR_CONNECTION_REFUSED»**

Причина: MAPS не запущен, туннелю некуда проксировать запросы.

Решение:
```bash
# Проверить MAPS
sudo systemctl status maps

# Запустить если остановлен
sudo systemctl start maps

# Убедиться что MAPS отвечает локально
curl http://localhost:8000/api/status
# Должно вернуть JSON с полем "status"

# Перезапустить туннель
sudo systemctl restart cloudflared-maps
```

---

**Ошибка: туннель не стартует, в логах «failed to sufficiently increase receive buffer»**

```
failed to sufficiently increase receive buffer size (was: 208 kiB, wanted: 7168 kiB)
```

Это предупреждение (не ошибка) — туннель работает, просто UDP-буфер меньше оптимального.
Никаких действий не требуется, соединение установится через TCP-fallback.

---

**Ошибка: туннель запустился, но URL не появляется в логах**

```bash
# Посмотреть полный лог с самого начала
sudo journalctl -u cloudflared-maps --no-pager | head -40

# Если видите "Requesting new quick Tunnel..." но нет URL — подождать 15 секунд
sleep 15
sudo journalctl -u cloudflared-maps --no-pager | grep trycloudflare.com
```

---

**Ошибка: два процесса cloudflared работают одновременно**

Симптом: в `ps aux | grep cloudflared` видно два процесса с разными PID.

```bash
# Найти все процессы
ps aux | grep cloudflared | grep -v grep

# Остановить сервис (он убьёт свой процесс)
sudo systemctl stop cloudflared-maps

# Убить оставшиеся вручную
sudo pkill -f cloudflared

# Запустить через сервис
sudo systemctl start cloudflared-maps
```

### 3.3 Вариант В — Постоянный Cloudflare туннель (именованный)

Для получения **постоянного URL** (не меняется при перезапусках) нужен бесплатный аккаунт Cloudflare.

#### Что потребуется

- Аккаунт на [cloudflare.com](https://cloudflare.com) (бесплатно)
- Домен, добавленный в Cloudflare (или использовать `*.cfargotunnel.com` без домена)

#### Шаг 1 — Аутентификация на сервере

Подключитесь к серверу по SSH (см. раздел 3.4) и выполните:

```bash
cloudflared tunnel login
```

Команда выведет ссылку вида `https://dash.cloudflare.com/...` — откройте её в браузере,
войдите в аккаунт Cloudflare и нажмите «Authorize». После этого на сервере появится
файл `~/.cloudflared/cert.pem`.

#### Шаг 2 — Создать именованный туннель

```bash
cloudflared tunnel create maps-tunnel
```

Команда создаст туннель и выведет его UUID (длинная строка вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`).
Запишите UUID — он понадобится на следующем шаге.

Туннель появится в дашборде Cloudflare: **Zero Trust → Networks → Tunnels**.

#### Шаг 3 — Создать конфигурационный файл

```bash
mkdir -p ~/.cloudflared
nano ~/.cloudflared/config.yml
```

Содержимое файла (подставьте ваш UUID):

```yaml
tunnel: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
credentials-file: /home/ubuntu/.cloudflared/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx.json

ingress:
  - service: http://localhost:8000
```

#### Шаг 4 — Привязать домен (если есть)

Если у вас есть домен на Cloudflare (например `example.com`), создайте DNS-запись:

```bash
cloudflared tunnel route dns maps-tunnel maps.example.com
```

После этого туннель будет доступен по адресу `https://maps.example.com`.

Если домена нет — туннель работает без DNS-имени, доступ через UUID:
`https://xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx.cfargotunnel.com`

#### Шаг 5 — Перенастроить systemd-сервис

Остановить текущий сервис и создать новый:

```bash
sudo systemctl stop cloudflared-maps
sudo systemctl disable cloudflared-maps

# Установить cloudflared как системный сервис (официальный способ)
sudo cloudflared service install
sudo systemctl enable cloudflared
sudo systemctl start cloudflared
```

#### Проверка

```bash
sudo systemctl status cloudflared
curl https://maps.example.com/api/status
```

### 3.4 Подключение к серверу по SSH

SSH нужен для управления сервером: просмотр логов, перезапуск сервисов, обновление кода.

#### Способ 1 — Oracle Cloud Shell (не требует ключей)

1. Откройте [cloud.oracle.com](https://cloud.oracle.com) в браузере
2. Нажмите иконку **`>_`** в правом верхнем углу — откроется встроенный терминал
3. Введите:

```bash
ssh ubuntu@132.145.232.46
```

Oracle Cloud Shell уже авторизован — пароли и ключи не нужны.
Подходит когда нет доступа к SSH-ключу или подключаетесь с чужого компьютера.

> **Ограничение:** Cloud Shell закрывается через ~20 минут неактивности. Долгие операции
> (например импорт данных) запускайте через `nohup ... &` или используйте `tmux`.

---

#### Способ 2 — SSH с локального компьютера (Linux/macOS)

SSH-ключ уже настроен в `~/.ssh/config` под алиасом `maps-server`.

**Короткая команда (через алиас):**
```bash
ssh maps-server
```

**Полная команда (если алиас не работает):**
```bash
ssh -i /home/dan/keys/oracle.pem ubuntu@132.145.232.46
```

**Содержимое `~/.ssh/config` (уже настроено):**
```
Host maps-server
    HostName 132.145.232.46
    User ubuntu
    IdentityFile /home/dan/keys/oracle.pem
    ServerAliveInterval 60
    ServerAliveCountMax 3
```

Параметры `ServerAlive` предотвращают разрыв соединения при простое.

---

#### Способ 3 — SSH с Windows (PowerShell / Windows Terminal)

На Windows 10/11 SSH встроен в систему.

**Вариант А — PowerShell с ключом PEM:**

Скопировать ключ на Windows-машину (например в `C:\Users\ИМЯ\.ssh\oracle.pem`).

> Права на ключ должны быть ограничены, иначе SSH откажет.
> Правой кнопкой на файл → Свойства → Безопасность → Дополнительно →
> Отключить наследование → Оставить только текущего пользователя с правом «Чтение».

```powershell
ssh -i C:\Users\ИМЯ\.ssh\oracle.pem ubuntu@132.145.232.46
```

**Вариант Б — PuTTY (конвертация ключа):**

PuTTY использует формат `.ppk`, а не `.pem`. Конвертация:

1. Скачать [PuTTYgen](https://www.putty.org/)
2. Открыть PuTTYgen → **File → Load private key** → выбрать `oracle.pem`
3. Нажать **Save private key** → сохранить как `oracle.ppk`
4. В PuTTY: Host = `ubuntu@132.145.232.46`, Port = 22
5. Connection → SSH → Auth → **Private key file** → выбрать `oracle.ppk`

#### Типичные ошибки SSH и их решение

**Ошибка: `Permission denied (publickey)`**

```
ubuntu@132.145.232.46: Permission denied (publickey)
```

Причины и решения:

| Причина | Решение |
|---------|---------|
| Неверный путь к ключу | Проверить: `ls -la /home/dan/keys/oracle.pem` — файл должен существовать |
| Неверные права на ключ | Исправить: `chmod 600 /home/dan/keys/oracle.pem` |
| Неверный пользователь | Для Oracle Ubuntu образов всегда `ubuntu`, не `root` или другой |
| Ключ не тот | Публичная часть ключа должна быть в `~/.ssh/authorized_keys` на сервере |

Быстрая диагностика:
```bash
# Показать какой ключ пытается использоваться
ssh -v maps-server 2>&1 | grep -E 'Trying|identity|publickey'
```

---

**Ошибка: `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED`**

```
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@ WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED! @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
```

Причина: отпечаток сервера в `~/.ssh/known_hosts` не совпадает с текущим.
Это нормально если сервер был пересоздан.

Решение:
```bash
# Удалить устаревший отпечаток
ssh-keygen -R 132.145.232.46

# Снова подключиться (система попросит подтвердить новый отпечаток)
ssh maps-server
# Ввести "yes" при вопросе "Are you sure you want to continue connecting?"
```

---

**Ошибка: `Connection timed out` или `Connection refused`**

| Ситуация | Причина | Решение |
|----------|---------|---------|
| `Connection timed out` | Файрвол блокирует порт 22 | Проверить Oracle Cloud Security List — должно быть правило TCP 22 для `0.0.0.0/0` |
| `Connection refused` | SSH сервис не запущен | Войти через Oracle Cloud Shell и выполнить `sudo systemctl start sshd` |
| `No route to host` | Сервер выключен | Запустить инстанс в Oracle Cloud Console |

---

**Ошибка: соединение обрывается само по себе через несколько минут**

Причина: NAT или файрвол разрывает «тихие» TCP-соединения.

Решение — добавить KeepAlive в `~/.ssh/config`:
```
Host maps-server
    HostName 132.145.232.46
    User ubuntu
    IdentityFile /home/dan/keys/oracle.pem
    ServerAliveInterval 60
    ServerAliveCountMax 3
```

Параметр `ServerAliveInterval 60` означает: каждые 60 секунд отправлять ping-пакет серверу,
чтобы соединение не считалось «тихим».

### 3.5 Управление сервисом MAPS

После подключения к серверу по SSH управляйте MAPS через `systemctl`:

```bash
# Проверить статус (работает ли MAPS)
sudo systemctl status maps

# Запустить MAPS (если остановлен)
sudo systemctl start maps

# Остановить MAPS
sudo systemctl stop maps

# Перезапустить (например после обновления кода)
sudo systemctl restart maps
```

**Что означает вывод `systemctl status`:**

```
● maps.service - MAPS — Material Allocation & Planning System
   Active: active (running)          ← ✅ всё хорошо, MAPS работает
   Active: activating (auto-restart) ← ⚠️ упал, пытается перезапуститься
   Active: failed                    ← ❌ упал и не может запуститься
```

**Если сервис циклически падает с ошибкой `address already in use`:**

В логах будет: `ERROR: [Errno 98] error while attempting to bind on address ('0.0.0.0', 8000): address already in use`

Причина: старый процесс uvicorn не освободил порт 8000.

```bash
# Узнать PID процесса на порту 8000
sudo ss -tlnp | grep 8000

# Убить его (подставить PID из вывода выше)
sudo kill -9 <PID>

# Перезапустить сервис
sudo systemctl restart maps
```

### 3.6 Просмотр логов MAPS

## 4. Ежедневная работа: полный цикл

Типичный рабочий день выглядит так:

```
1. Открыть Cloud Shell → запустить туннель → открыть дашборд
2. Загрузить обновлённые Excel-файлы (потребности, склад, поставки)
3. Нажать "Запустить распределение"
4. Скачать Excel-отчёт
5. (Опционально) Согласованные перемещения:
   Если в отчёте есть «Возможное перемещение» — согласуйте нужные позиции
   с другими филиалами, загрузите файл через «Согласованные перемещения (Шаг 2)»,
   запустите распределение повторно
6. При необходимости — воспользоваться AI-анализом дефицита
```

### Шаг 1 — Открыть дашборд

```bash
# На сервере (Cloud Shell — НЕ на локальном компьютере!):
cd ~/maps
bash deploy/tunnel.sh --bg
cat /tmp/maps_tunnel.url
# → Скопировать ссылку и открыть в браузере
```

> **Частые ошибки:**
> - Команды туннеля нужно запускать **на сервере** (через Cloud Shell или SSH), а не в локальном терминале. Если видите `No such file or directory: /home/dan/maps` — вы в локальном терминале.
> - URL туннеля виден сразу в выводе `tunnel.sh --bg`, даже если `cat` команда не сработала.

### Шаг 2 — Загрузить данные

В дашборде справа — панель **«Импорт файлов»**. Раскройте нужный раздел и выберите файл.

Рекомендуемый порядок загрузки:
1. **Перечень работ** ← загружать первым: устанавливает даты, наименования и оргструктуру
2. Потребности
3. Аварийные работы (если есть) ← тот же формат, что и «Перечень работ»
4. Потребности аварийных работ ← тот же формат, что и «Потребности»
5. Складские остатки
6. Поставки
7. Списания
8. Выдано не списано

После каждой загрузки появится статистика: сколько строк загружено и сколько ошибок.

### Шаг 3 — Запустить распределение

Нажмите кнопку **«Запустить распределение»** в левой панели.
Кнопка станет неактивной, появится индикатор загрузки.
Через несколько секунд в карточке «Текущие результаты» появится статистика: потребности, строки распределения, дефицит.

### Шаг 4 — Скачать отчёт

В карточке **«Текущие результаты»** нажмите **«Скачать Excel-отчёт»**.
Браузер скачает файл вида `MAPS_отчёт_20260524_....xlsx`.

## 5. Загрузка данных подробно

### Порядок важен!

Списания и «Выдано не списано» ссылаются на работы.
Если загрузить их **до** потребностей — строки будут пропущены с ошибкой `«Работа не найдена»`.

**Правильный порядок:**
```
1. Перечень работ                ← устанавливает наименования и даты начала/окончания работ
2. Потребности                   ← материалы по работам; работы должны уже быть загружены
3. Аварийные работы              ← добавляет аварийные работы (формат как у «Перечня работ»)
4. Потребности аварийных работ   ← материалы аварийных работ (формат как у «Потребностей»)
5. Складские остатки             ← загружает партии на склад
6. Поставки                      ← загружает ожидаемые поставки («в пути»)
7. Списания                      ← ссылается на работы из шага 1
8. Выдано не списано             ← ссылается на работы из шага 1
9. Согласованные перемещения     ← только после первого запуска распределения
```

> **Важно:** Файл «Потребности» НЕ создаёт работы. Если работа с нужным кодом не найдена —
> строка пропускается с предупреждением в лог. Загрузите «Перечень работ» первым.

### Повторная загрузка (обновление данных)

Загружать файлы можно сколько угодно раз. Все типы файлов работают по принципу **полной замены**:

| Файл | Поведение |
|---|---|
| Перечень работ | Upsert: обновляет наименование и даты для существующих работ, создаёт новые |
| Потребности | Старые плановые потребности удаляются, загружаются новые |
| Аварийные работы | Старые аварийные потребности удаляются, загружаются новые |
| Склад | Старые партии удаляются, загружаются новые |
| Поставки | Старые поставки удаляются, загружаются новые |
| Списания | Старые записи удаляются, загружаются новые |
| Выдано не списано | Старые записи удаляются, загружаются новые |
| Согласованные перемещения | Старые записи удаляются, загружаются новые |

> **Формат дат и чисел в Excel-файлах:** все файлы принимаются в русском формате — дата ДД.ММ.ГГГГ (например 28.05.2026), разделитель дробной части — запятая (например 1234,56). ISO-формат дат (ГГГГ-ММ-ДД) тоже поддерживается.

**Система всегда работает с актуальными данными** — при загрузке потребностей все предыдущие данные (работы, потребности, результаты распределения) полностью удаляются и заменяются новыми. История не хранится.

### Загрузка через curl (без браузера)

Можно загружать файлы из командной строки. Удобно для автоматизации:

```bash
# С локального компьютера (замените URL на ваш туннельный)
TUNNEL=https://xxxx.trycloudflare.com

curl -X POST $TUNNEL/api/import/works                    -F "file=@путь/к/перечень_работ.xlsx"
curl -X POST $TUNNEL/api/import/requirements             -F "file=@путь/к/потребности.xlsx"
curl -X POST $TUNNEL/api/import/emergency                -F "file=@путь/к/аварийные_работы.xlsx"
curl -X POST $TUNNEL/api/import/emergency-requirements   -F "file=@путь/к/аварийные_потребности.xlsx"
curl -X POST $TUNNEL/api/import/stock                    -F "file=@путь/к/склад.xlsx"
curl -X POST $TUNNEL/api/import/supplies                 -F "file=@путь/к/поставки.xlsx"
curl -X POST $TUNNEL/api/import/writeoffs                -F "file=@путь/к/списания.xlsx"
curl -X POST $TUNNEL/api/import/issued                   -F "file=@путь/к/выдано.xlsx"
```

Ответ при успехе (потребности):
```json
{"status": "ok", "stats": {"requirements": 1200, "skipped": 5, "errors": 0}}
```

Если в поле `errors` не ноль — посмотрите логи сервера:
```bash
sudo journalctl -u maps -n 50 --no-pager | grep -i error
```

### Форматы Excel-файлов

Названия колонок в файле должны совпадать с ожидаемыми. Если колонки названы иначе — строки будут пропущены без ошибки (просто не загрузятся).

**Перечень работ** (загружать первым):

| Колонка | Обязательна | Пример |
|---|---|---|
| Код работы | ✅ | WO-001 |
| Наименование работы | нет | Ремонт насосной станции НС-6 |
| Тип работы | нет | Ремонт |
| Филиал | нет | Алматы |
| Подразделение | нет | Цех 1 |
| Центр затрат | нет | CC-KZ01-001 |
| Завод | нет | KZ01 |
| Дата начала | нет | 2026-06-01 |
| Дата окончания | нет | 2026-07-31 |
| Приоритет | нет | 1 |
| Статус | нет | active |

> Даты начала и окончания **берутся только из этого файла**. В файле потребностей дат нет.
>
> **Допустимые значения поля «Статус»:**
> - `active` — работа активна (полное распределение всех слоёв)
> - `completed` или `завершена` — работа завершена (только слои 1–2: списание и выдано; склад не берётся)
> - `on_hold` — работа приостановлена (пропускается алгоритмом полностью)
> - `cancelled` — работа отменена (пропускается алгоритмом полностью)

**Потребности** (новый формат, только материальные данные — без оргструктуры):

| Колонка | Обязательна | Пример |
|---|---|---|

| Системный номер | ✅ | MAT-001 |

| Ед.изм | нет | м |
| Потребность | ✅ | 100 |
| Прогнозная цена | нет | 1200 |

**Потребности аварийных работ** — тот же формат, что и обычные «Потребности».

| Наименование материала | нет | Кабель ВВГ 3х2,5 мм |
| Ед.изм | нет | м |

## 6. Запуск распределения и скачивание отчёта

### Через дашборд

1. Нажмите **«Запустить распределение»**
2. Дождитесь статуса 🟢 «завершено» (обычно 5–30 секунд)
3. Нажмите **«Скачать Excel»**

### Через API (curl)

```bash
# Запустить распределение
curl -X POST http://localhost:8000/api/allocate

# Проверить текущий статус
curl http://localhost:8000/api/status

# Скачать отчёт текущей сессии (ID берём из maps show или maps status)
curl -O -J http://localhost:8000/api/export/20260524_083028_f8db0
```

### Что означают числа в итогах сессии

```json
{
  "total_requirements": 16,   ← сколько строк потребностей обработано
  "total_allocated": 19,      ← сколько строк результатов создано (может быть > requirements,
                                 если материал берётся из нескольких партий)
  "total_deficit": 14         ← сколько позиций в дефиците
}
```

### Структура Excel-отчёта

Полный отчёт содержит до 16 листов (лист «Одобренные перемещения» появляется только если они были загружены).

**Результаты распределения:**

| № | Лист | Что там |
|---|---|---|
| 1 | Распределение | Полная таблица: работа, материал, все слои в одной строке (Сп-е / Выд-но / Склад / Одобр. / Поставки / К закупу / %) |
| 2 | Движение склада | Детально по партиям: что взято, откуда, сколько |
| 3 | Остатки складов (итог) | Что осталось на складе после распределения |
| 4 | Возможное перемещение | Материалы которых нет на своём складе, но есть на складе другого филиала |
| 5 | Шаблон подтверждения | Шаблон для согласования перемещений (заполните «Кол-во согласовано» и загрузите через `/api/import/transfers`) |
| 6 | Одобренные перемещения | Слой 3в: реально использованные согласованные перемещения |
| 7 | Обеспеченность | Сводная таблица по работам: стоимость потребности, покрытия и дефицита, % обеспеченности |
| 8 | Распределение «в пути» | Поставки («в пути»), распределённые на конкретные работы в этой сессии |
| 9 | Не распред. в пути | Строки поставок с остатком после распределения |
| 10 | Дефицит | Материалы к закупу: все поля для формирования заявки на закупку |

**Исходные данные (для аудита и сверки):**

| № | Лист | Что там |
|---|---|---|
| 11 | Исх. Перечень работ | Все работы с датами, статусами, количеством материалов |
| 12 | Исх. Потребности | Все потребности до распределения: код работы, группа, номер и наименование материала, потребность, прогнозная цена и стоимость. Без дат и статусов (они на листе «Исх. Перечень работ») |
| 13 | Исх. Остатки складов | Начальные остатки складов до распределения |
| 14 | Исх. Поставки | Все строки поставок |
| 15 | Исх. Списания | Фактические списания (Слой 1 — исходные данные) |
| 16 | Исх. Выдано не списано | Выданные, но не списанные материалы (Слой 2 — исходные данные) |

> Числа в отчёте: разделитель «,» (запятая). Даты: формат ДД.ММ.ГГГГ.

### Работа с согласованными перемещениями (Слой 3в)

Это дополнительный шаг после первого распределения. Нужен когда после обычного распределения остался дефицит, но в листе «Возможное перемещение» видно что нужный материал есть на складе другого филиала.

**Порядок действий:**

1. Запустите обычное распределение → скачайте отчёт
2. Откройте лист «Возможное перемещение» — там список материалов с другого склада
3. Согласуйте нужные перемещения с другими филиалами
4. Подготовьте Excel-файл со согласованными перемещениями:

| Колонка | Обязательна | Пример |
|---|---|---|
| Системный номер | ✅ | MAT-001 |
| Склад-источник | ✅ | WH-KZ02-001 |
| Филиал-получатель | ✅ | Алматы |
| Кол-во согласовано | ✅ | 50 |

Альтернативные заголовки: «Возможное кол-во» вместо «Кол-во согласовано», «Куда (филиал)» вместо «Филиал-получатель».

5. В дашборде раскройте аккордеон **«Согласованные перемещения (Слой 3в) — Шаг 2»** (оранжевая рамка) → загрузите файл
6. Нажмите «Запустить распределение» повторно
7. Скачайте новый отчёт — теперь в листе «Одобренные перемещения» появятся данные, а дефицит уменьшится

**Важно:** каждая загрузка файла согласованных перемещений ПОЛНОСТЬЮ заменяет предыдущие записи.

**Через curl:**
```bash
TUNNEL=https://xxxx.trycloudflare.com
curl -X POST $TUNNEL/api/import/transfers \
     -F "file=@/home/dan/Downloads/approved_transfers.xlsx"
```

## 7. AI-функции

Для работы AI нужен `ANTHROPIC_API_KEY` в файле `.env`.
Без него всё остальное работает нормально, только AI-кнопки вернут ошибку 503.

### Объяснение дефицита

В дашборде внизу — синий блок **«AI-анализ дефицита»**:
1. После запуска распределения список материалов с дефицитом заполняется автоматически
2. Выберите материал из выпадающего списка
3. Нажмите «Объяснить»
4. Claude объяснит на русском почему не хватило материала и что делать

AI анализирует текущую сессию — почему не хватило конкретного материала, что покрыло какой слой, чего не хватало. Если дефицита нет — список будет пустым.

## 8. Обновление кода на сервере

Когда разработчик пушит изменения в GitHub — их нужно применить на сервере вручную:

```bash
# На сервере (Cloud Shell):
cd ~/maps

# Скачать последние изменения из GitHub
git pull origin main

# Перезапустить MAPS чтобы изменения вступили в силу
sudo systemctl restart maps

# Убедиться что запустился нормально
sudo systemctl status maps
```

Если после `git pull` сервис не запустился — смотрите логи:
```bash
sudo journalctl -u maps -n 30 --no-pager
```

### Проблема: тестовые и реальные данные смешались

**Что происходит:**  
Вы загрузили реальные потребности (199 строк) поверх тестовых данных.
В БД остались и те и другие. При запуске распределения все 215 строк
конкурируют за один и тот же (тестовый) склад — реальные результаты некорректны.

**Как определить что данные смешались:**
- Количество потребностей неожиданно большое
- В отчёте видны коды работ вида `WO-SCN-01`, `AV-SCN-06` (тестовые)
- Обеспечённость неожиданно низкая (почти всё в дефиците)

**Решение — полная очистка и загрузка только реальных данных:**

```bash
# На сервере: остановить MAPS
sudo systemctl stop maps

# Сбросить все данные через psql
sudo -u postgres psql -d maps_db -c "
TRUNCATE TABLE deficit_records, allocation_results, stock_movements,
  allocation_sessions, issued_not_written_offs, write_offs,
  supply_lines, supplies, stock_batches, warehouses,
  requirements, works, materials
  RESTART IDENTITY CASCADE;
"

# Запустить снова
sudo systemctl start maps
```

После этого загружайте только реальные файлы через дашборд в правильном порядке:
1. Потребности (реальные)
2. Аварийные работы (реальные, если есть)
3. Складские остатки (реальные)
4. Поставки (реальные)
5. Списания (реальные)
6. Выдано не списано (реальные)


Если видите строки с `WO-SCN-*` или `AV-SCN-*` — тестовые данные присутствуют.

### Частичная очистка: удалить только тестовые записи

Если реальные данные уже загружены и не хочется всё удалять — можно точечно удалить только тестовые работы по паттерну кода.

**Пример: удалить тестовые аварийные работы (AV-SCN-*)**

Важно: несколько таблиц ссылаются на `works` через `work_id`. Удалять нужно строго по порядку — от дочерних таблиц к родительской. Если пропустить хоть одну — PostgreSQL выдаст ошибку FK и не даст удалить работу.

Полный правильный порядок:

```bash
# 1. stock_movements ссылается на works
sudo -u postgres psql -d maps_db -c "DELETE FROM stock_movements WHERE work_id IN (SELECT id FROM works WHERE kod_raboty LIKE 'AV-SCN%')"

# 2. allocation_results ссылается на works
sudo -u postgres psql -d maps_db -c "DELETE FROM allocation_results WHERE work_id IN (SELECT id FROM works WHERE kod_raboty LIKE 'AV-SCN%')"

# 3. deficit_records ссылается на works
sudo -u postgres psql -d maps_db -c "DELETE FROM deficit_records WHERE work_id IN (SELECT id FROM works WHERE kod_raboty LIKE 'AV-SCN%')"

# 4. requirements ссылается на works
sudo -u postgres psql -d maps_db -c "DELETE FROM requirements WHERE work_id IN (SELECT id FROM works WHERE kod_raboty LIKE 'AV-SCN%')"

# 5. Теперь можно удалить сами работы
sudo -u postgres psql -d maps_db -c "DELETE FROM works WHERE kod_raboty LIKE 'AV-SCN%'"

# 6. Проверяем — должно быть 0
sudo -u postgres psql -d maps_db -c "SELECT COUNT(*) FROM works WHERE kod_raboty LIKE 'AV-SCN%'"
```

**Пример: удалить все тестовые обычные работы (WO-SCN-*)**

Тот же порядок, только паттерн другой:

```bash
sudo -u postgres psql -d maps_db -c "DELETE FROM stock_movements WHERE work_id IN (SELECT id FROM works WHERE kod_raboty LIKE 'WO-SCN%')"
sudo -u postgres psql -d maps_db -c "DELETE FROM allocation_results WHERE work_id IN (SELECT id FROM works WHERE kod_raboty LIKE 'WO-SCN%')"
sudo -u postgres psql -d maps_db -c "DELETE FROM deficit_records WHERE work_id IN (SELECT id FROM works WHERE kod_raboty LIKE 'WO-SCN%')"
sudo -u postgres psql -d maps_db -c "DELETE FROM requirements WHERE work_id IN (SELECT id FROM works WHERE kod_raboty LIKE 'WO-SCN%')"
sudo -u postgres psql -d maps_db -c "DELETE FROM works WHERE kod_raboty LIKE 'WO-SCN%'"
```

**Как узнать какая таблица блокирует удаление:**

Если получили ошибку вида:
```
ERROR: update or delete on table "works" violates foreign key constraint
"stock_movements_work_id_fkey" on table "stock_movements"
```
— в тексте ошибки написано точное название таблицы (`stock_movements`). Сначала удалите записи из неё, потом повторите удаление работы.

После удаления тестовых данных запустите распределение заново — результат будет корректным:

```bash
maps allocate
maps show   # проверить результат
```

**Почему нельзя просто удалить через `maps reset-data`:**  
`maps reset-data` удаляет ВСЁ включая реальные данные и историю сессий. Точечное удаление через psql сохраняет реальные данные нетронутыми.

**Как понять что очистка помогла:**  
Запустите `maps show` после нового `maps allocate` — если количество дефицита стало меньше, значит тестовые данные действительно мешали.

## 10. Работа с GitHub

### Зачем нужен GitHub

GitHub — это облачное хранилище кода. Он выполняет три роли:

1. **Резервная копия** — код не потеряется если что-то случится с компьютером
2. **История изменений** — можно посмотреть что и когда изменили, откатиться назад
3. **Мост между компьютерами** — изменения сделанные на локальном компьютере попадают на сервер через GitHub

```
Локальный компьютер  ──git push──►  GitHub  ──git pull──►  Сервер Oracle Cloud
```

## 11. Типичные ошибки и как их исправить

### Ошибка 0: «Расчёт уже выполняется» (HTTP 409)

**Что видите:** При нажатии «Запустить распределение» появляется сообщение:
```
Расчёт уже выполняется. Дождитесь завершения текущего запуска.
```

**Причина:** Другой пользователь (или вкладка браузера) уже запустил расчёт, и он ещё не завершился. Система намеренно блокирует второй запуск — одновременные расчёты приведут к повреждению данных (второй запуск удаляет результаты первого прямо во время работы).

**Решение:** Подождите, пока карточка «Последнее распределение» на дашборде покажет статус «Завершено» или «Ошибка». После этого кнопка снова станет активной.

**Если расчёт завис** (статус «running» больше 10 минут, прогресс не меняется):
```bash
# На сервере — перезапустить MAPS
sudo systemctl restart maps
```
После перезапуска блокировка сбрасывается автоматически.

### Ошибка 2: Дашборд отдаёт «Not Found»

**Что видите:** Белая страница с текстом «Not Found. The requested URL was not found on the server.»

**Причина:** MAPS запущен, но приложение упало при старте и маршруты не зарегистрированы.

**Диагностика и решение:**

```bash
# На сервере: смотрим логи

# Возможная ошибка 1: ModuleNotFoundError: No module named 'anthropic'
# Решение: установить пакет вручную

# Возможная ошибка 2: address already in use (порт занят)
# Решение:
sudo fuser -k 8000/tcp
sleep 2
sudo systemctl restart maps

# Возможная ошибка 3: --workers 2 (многопроцессный режим не работает на Oracle Cloud)
# Проверить:
grep ExecStart /etc/systemd/system/maps.service
# Если там есть --workers 2 — убрать:
sudo sed -i '/--workers/d' /etc/systemd/system/maps.service
sudo systemctl daemon-reload
sudo systemctl restart maps
```

### Ошибка 6: «address already in use» — порт занят

**Что видите в браузере:** Туннель открыт и URL есть, но страница отдаёт «Not Found».

**Что видите в логах:**
```
ERROR: [Errno 98] error while attempting to bind on address ('0.0.0.0', 8000): address already in use
maps.service: Scheduled restart job, restart counter is at 9732.
```

**Причина:** Предыдущий процесс uvicorn не завершился (например при `systemctl stop` воркеры зависли).
MAPS циклически перезапускается, каждый раз упираясь в занятый порт. Счётчик `restart counter` может быть очень большим — это нормально, главное освободить порт.

Cloudflare туннель при этом «успешно» подключается к старому зависшему процессу на порту 8000 — поэтому URL есть, но возвращается 404 вместо дашборда.

**Решение:**

```bash
# Найти и убить всё что занимает порт 8000
sudo fuser -k 8000/tcp

# Подождать 2 секунды и перезапустить
sleep 2
sudo systemctl restart maps

# Убедиться что запустился (должно быть active (running))
sudo systemctl status maps

# Проверить что API отвечает
curl http://localhost:8000/api/status
```

После этого обновите страницу в браузере — дашборд откроется.

### Ошибка 8: `ModuleNotFoundError: No module named 'main'` при вызове `maps`

**Что видите:**
```
Traceback (most recent call last):
  File "/home/ubuntu/maps/.venv/bin/maps", line 3, in <module>
    from main import app
ModuleNotFoundError: No module named 'main'
```

**Причина:** Скрипт `.venv/bin/maps` устарел и содержит старую точку входа. Это происходит когда `pip install -e .` не пересоздаёт скрипт — старый файл остаётся нетронутым.

**Решение — полная переустановка:**
```bash
cd ~/maps
git pull origin main          # сначала получить свежий код
pip uninstall maps -y         # удалить старый пакет (и скрипт)
pip install -e .              # установить заново — скрипт пересоздастся
maps show                     # проверить что работает
```

**Почему `pip install -e .` недостаточно:**  
Pip не перезаписывает уже существующий скрипт `.venv/bin/maps` если считает что пакет уже установлен.
`pip uninstall` удаляет скрипт, после чего `pip install` создаёт его заново с правильной точкой входа.

**Важно:** всегда делайте `git pull` ДО переустановки — иначе установится старая версия кода.

## 12. Работа через командную строку (CLI)

### Что такое CLI и зачем он нужен

CLI (Command Line Interface) — это управление системой через команды в терминале вместо браузера и мышки.

**Когда CLI удобнее дашборда:**

| Задача | Дашборд | CLI |
|---|---|---|
| Загрузить файл мышкой | ✅ удобно | можно |
| Загрузить 5 файлов подряд скриптом | неудобно | ✅ удобно |
| Посмотреть статус не открывая браузер | — | ✅ одна команда |
| Запустить распределение по расписанию (cron) | ❌ нельзя | ✅ легко |
| Посмотреть детали сессии в терминале | — | ✅ |
| Загрузить файл на сервере без браузера | ❌ нельзя | ✅ |

### Как активировать CLI

Перед использованием команды `maps` нужно активировать виртуальное окружение:

```bash
# На локальном компьютере
cd ~/dev/projects/python/PythonProject
source .venv/bin/activate

# На сервере
cd ~/maps
source .venv/bin/activate
```

После активации в начале строки появится `(.venv)`:
```
(.venv) dan@computer:~/dev/projects/python/PythonProject$
```

Теперь можно писать команды. Чтобы выйти из виртуального окружения:
```bash
deactivate
```

### Если команда `maps` не найдена или выдаёт ошибку ModuleNotFoundError

После `git pull` (обновления кода с GitHub) нужно переустановить пакет, чтобы точка входа `maps` обновилась:

```bash
cd ~/maps
source .venv/bin/activate
pip install -e .
```

Что делает `pip install -e .`:
- `-e` (editable) — устанавливает пакет в «режиме разработки»: изменения в коде сразу видны без переустановки
- `.` — текущая папка (читает `pyproject.toml` для настроек)
- Регистрирует точку входа `maps` — создаёт скрипт `.venv/bin/maps` который запускает `main.py`

**Когда нужно запускать `pip install -e .`:**
- При первоначальной установке (делает `setup.sh` автоматически)
- После `git pull` если добавлены новые зависимости в `pyproject.toml`
- Если команда `maps` внезапно перестала работать с ошибкой `ModuleNotFoundError`

**Если `pip install -e .` не помогло** — скрипт `.venv/bin/maps` устарел, нужна полная переустановка:
```bash
pip uninstall maps -y
pip install -e .
```

Пока не переустановили — можно использовать `python main.py` вместо `maps`:
```bash
python main.py status
python main.py show
python main.py allocate
```

### Правильный порядок обновления CLI на сервере

После каждого `git pull` который затрагивает `main.py` или `pyproject.toml`:

```bash
cd ~/maps
git pull origin main
pip uninstall maps -y    # удаляем старый скрипт
pip install -e .         # создаём новый скрипт с актуальной точкой входа
sudo systemctl restart maps  # перезапускаем веб-сервер
```

Если изменялись только файлы в `app/` или `docs/` — `pip uninstall/install` не нужен, достаточно `sudo systemctl restart maps`.

## 13. Передача данных на сервер

Есть три способа загрузить Excel-файлы на сервер. Выбирайте в зависимости от ситуации.

| Способ | Когда использовать | Сложность |
|---|---|---|
| Дашборд (браузер) | Разовая загрузка, удобно для нетехнических пользователей | ⭐ просто |
| curl (API) | Загрузка нескольких файлов скриптом, автоматизация | ⭐⭐ средне |
| SCP (прямая копия) | Нет браузера, нужна работа с файлами на сервере через CLI | ⭐⭐⭐ сложнее |

---

### Способ 1 — Через дашборд (браузер)

Самый простой способ. Не требует никаких дополнительных инструментов.

**Шаги:**

1. На сервере запустите туннель:
```bash
cd ~/maps
bash deploy/tunnel.sh --bg
cat /tmp/maps_tunnel.url
```

2. Откройте полученный URL в браузере (вида `https://xxxx.trycloudflare.com`)

3. В правой панели дашборда раскройте нужный раздел (например «Потребности»)

4. Нажмите «Выбрать файл», выберите Excel-файл на вашем компьютере, нажмите «Загрузить»

5. Дождитесь сообщения об успешной загрузке со статистикой

**Ограничения:**
- Туннель должен быть запущен и URL — актуальным
- Каждый файл загружается отдельно через интерфейс
- Размер файла ограничен настройками сервера (обычно до 100 МБ)

---

### Способ 2 — Через curl (API запросы)

Загрузка файлов напрямую через HTTP API с вашего компьютера. Удобно когда нужно загрузить несколько файлов подряд или автоматизировать процесс.

**Требования:** туннель должен быть запущен, `curl` установлен (есть по умолчанию на Linux и Mac).

#### Разовая загрузка одного файла

```bash
# Сначала сохраните URL туннеля в переменную
TUNNEL=https://xxxx.trycloudflare.com   # замените на реальный URL

# Загрузить потребности
curl -X POST $TUNNEL/api/import/requirements \
     -F "file=@/home/dan/Downloads/requirements.xlsx"
```

Флаг `-F "file=@путь"` означает: отправить файл как form-data (так же как через браузер).
Знак `@` перед путём — указание что это файл, а не текст.

Ответ при успехе:
```json
{"status": "ok", "stats": {"works": 63, "requirements": 199, "errors": 0}}
```

#### Загрузка всех файлов скриптом

Создайте файл `load_data.sh` на локальном компьютере:

```bash
#!/bin/bash
# load_data.sh — загружает все файлы на сервер через API

TUNNEL=https://xxxx.trycloudflare.com   # ← вставьте актуальный URL туннеля
DATA_DIR=/home/dan/Downloads/maps_data  # ← папка с вашими Excel-файлами

echo "Загрузка перечня работ..."
curl -s -X POST $TUNNEL/api/import/works \
     -F "file=@$DATA_DIR/works.xlsx" | python3 -m json.tool

echo "Загрузка потребностей..."
curl -s -X POST $TUNNEL/api/import/requirements \
     -F "file=@$DATA_DIR/requirements.xlsx" | python3 -m json.tool

echo "Загрузка аварийных работ..."
curl -s -X POST $TUNNEL/api/import/emergency \
     -F "file=@$DATA_DIR/emergency.xlsx" | python3 -m json.tool

echo "Загрузка складских остатков..."
curl -s -X POST $TUNNEL/api/import/stock \
     -F "file=@$DATA_DIR/stock.xlsx" | python3 -m json.tool

echo "Загрузка поставок..."
curl -s -X POST $TUNNEL/api/import/supplies \
     -F "file=@$DATA_DIR/supplies.xlsx" | python3 -m json.tool

echo "Загрузка списаний..."
curl -s -X POST $TUNNEL/api/import/writeoffs \
     -F "file=@$DATA_DIR/writeoffs.xlsx" | python3 -m json.tool

echo "Загрузка выдано не списано..."
curl -s -X POST $TUNNEL/api/import/issued \
     -F "file=@$DATA_DIR/issued.xlsx" | python3 -m json.tool

echo "Готово! Запустите распределение через дашборд или:"
echo "  curl -X POST $TUNNEL/api/allocate"
```

Запуск скрипта:
```bash
chmod +x load_data.sh   # дать права на выполнение (один раз)
./load_data.sh          # запустить
```

Флаг `-s` (silent) убирает прогресс-бар curl, `| python3 -m json.tool` красиво форматирует JSON-ответ.

#### Запуск распределения через curl

```bash
# Запустить распределение
curl -X POST $TUNNEL/api/allocate

# Проверить текущий статус
curl -s $TUNNEL/api/status | python3 -m json.tool

# Скачать отчёт (ID берём из maps show на сервере)
curl -O -J $TUNNEL/api/export/20260524_143055_a1b2c
# -O — сохранить в файл, -J — использовать имя файла из заголовка ответа
```

**Ограничения:**
- Нужен активный туннель
- URL туннеля меняется при каждом перезапуске — нужно обновлять в скрипте
- Если туннель закрылся в процессе — загрузка прервётся

### Способ 3 — Через SCP (прямая копия файлов)

SCP (Secure Copy) — копирование файлов напрямую на сервер по SSH, без туннеля и браузера.
После копирования файлы появляются на сервере и можно загружать их через CLI (`maps import-*`).

**Требования:** настроенный SSH-ключ для подключения к серверу.

#### SSH-ключ для подключения к серверу

SSH-ключ уже настроен и лежит по пути:
```
/home/dan/keys/oracle.pem
```

Подключение к серверу с локального компьютера:
```bash
ssh -i /home/dan/keys/oracle.pem ubuntu@132.145.232.46
```

Флаг `-i` (identity) — указывает путь к файлу ключа.
`.pem` — формат ключа Oracle Cloud (приватный ключ, никому не передавать).

#### Копирование файлов через SCP

SCP использует тот же ключ что и SSH — добавьте `-i /home/dan/keys/oracle.pem`:

```bash
# Скопировать один файл на сервер
scp -i /home/dan/keys/oracle.pem \
    /home/dan/Downloads/requirements.xlsx \
    ubuntu@132.145.232.46:~/maps/data/

# Скопировать несколько файлов сразу
scp -i /home/dan/keys/oracle.pem \
    requirements.xlsx stock.xlsx supplies.xlsx \
    ubuntu@132.145.232.46:~/maps/data/

# Скопировать всю папку с файлами
scp -i /home/dan/keys/oracle.pem -r \
    /home/dan/Downloads/maps_data/ \
    ubuntu@132.145.232.46:~/maps/data/
```

Флаг `-r` (recursive) — копировать папку со всем содержимым.

Добавьте в файл `~/.ssh/config` на локальном компьютере:

### Полный рабочий цикл через SCP + CLI (пошагово с реальными примерами)

Это полный разбор того как загрузить файлы через SCP и импортировать их через CLI.
Все команды проверены на практике.

#### Шаг 1 — Подготовить папку на сервере

Перед первой загрузкой создайте папку для данных на сервере.
Выполняется **на сервере** (через Cloud Shell):


#### Шаг 2 — Скопировать файлы через SCP

Выполняется **на локальном компьютере** (не в Cloud Shell!).
Важно: команда должна быть в **одну строку** — вставка многострочной команды с `\` может не сработать.

```bash
# Скопировать папку с тестовыми данными целиком
scp -i /home/dan/keys/oracle.pem -r /home/dan/dev/projects/python/PythonProject/data/test/ ubuntu@132.145.232.46:~/maps/data/test/
```

```
test_writeoffs.xlsx     100% 5315    58.7KB/s   00:00
test_emergency.xlsx     100% 5610    59.0KB/s   00:00
test_requirements.xlsx  100% 6555    67.6KB/s   00:00
test_issued.xlsx        100% 5178    54.1KB/s   00:00
```

Если папка назначения уже существовала до SCP, файлы могут попасть на уровень глубже:
```

```

Проверьте:

Выполняется **на сервере**. Порядок важен — потребности первыми:

```bash
cd ~/maps
source .venv/bin/activate

maps import-requirements data/test/test_requirements.xlsx

maps import-writeoffs    data/test/test_writeoffs.xlsx
maps import-issued       data/test/test_issued.xlsx
```

Каждая команда выводит таблицу с результатом. Пример для потребностей:
```

    Результат импорта: Потребности
┏━━━━━━━━━━━━━━┳━━━━━━━━━━┓
┃ Показатель   ┃ Значение ┃
┡━━━━━━━━━━━━━━╇━━━━━━━━━━┩
│ works        │        0 │   ← 0 потому что работы уже есть в БД

│ errors       │        0 │   ← ошибок нет ✅
└──────────────┴──────────┘
```

Что означает `works = 0`:
Работы создаются при первой загрузке. При повторной загрузке потребностей для тех же работ — новые работы не создаются, считается 0. Это нормально.

**На что смотреть:**
- `errors = 0` — всё загружено без ошибок ✅
- `skipped > 0` — часть строк пропущена (обычно потому что работа не найдена — нужно сначала загрузить потребности)
- `errors > 0` — смотреть логи: `sudo journalctl -u maps -n 30 --no-pager`

#### Шаг 4 — Запустить распределение и проверить результат

```bash

```

Пример вывода `maps show` после чистого тестового прогона:

```
│ Завершена: 2026-05-24 06:05:15         │

  Строк распределения         19
  Позиций дефицита (К закупу)  8
```

**Как читать результат:**
- `16 потребностей` = 13 обычных + 3 аварийных ✅
- `19 строк распределения` > 16 потребностей — нормально, один материал может покрываться из нескольких источников
- `8 дефицит` — 8 позиций к закупу (не хватило материала)

## 14. Аутентификация дашборда

Дашборд защищён логином и паролем. Без входа в систему все страницы перенаправляют на форму входа `/login`.

### 14.1 Тестовый пользователь (по умолчанию)

При первом запуске в системе создан один пользователь:

| Параметр | Значение |
|----------|----------|
| Логин    | `admin`  |
| Пароль   | `CHANGE_ME` |

> **Важно:** Это учётные данные по умолчанию для разработки. На production-сервере обязательно замените пароль на сложный (см. раздел 14.3).

### 14.2 Как устроена аутентификация

MAPS использует **сессионные cookie** (подписанные через `itsdangerous`):

1. Пользователь вводит логин и пароль на странице `/login`
2. Сервер сравнивает введённые данные с переменными `MAPS_USERNAME` и `MAPS_PASSWORD` из файла `.env`
3. Если данные верны — создаётся подписанная сессионная cookie (`maps_session`)
4. Cookie действует **24 часа**, после чего нужно войти снова
5. Кнопка «Выйти» в навбаре очищает cookie — следующий запрос снова попросит войти

Сравнение паролей использует `hmac.compare_digest` — это защищает от атак по времени (timing attack), когда злоумышленник пытается угадать пароль по скорости ответа сервера.

Сессионная cookie подписана ключом `SECRET_KEY`. Если ключ утечёт — смените его (все активные сессии при этом автоматически инвалидируются).

### 14.3 Как сменить логин или пароль

Логин и пароль хранятся в файле `.env` на сервере. Там же хранится секретный ключ подписи сессий.

**На сервере Oracle Cloud:**

```bash
# Подключиться к серверу
ssh -i /home/dan/keys/oracle.pem ubuntu@132.145.232.46

# Открыть .env в текстовом редакторе
nano /home/ubuntu/maps/.env
```

Найти и изменить строки:

```
MAPS_USERNAME=admin
MAPS_PASSWORD=CHANGE_ME
```

Поменять на нужные значения, например:

```
MAPS_USERNAME=operator
MAPS_PASSWORD=ВашНовыйСложныйПароль123!
```

Сохранить файл: `Ctrl+O`, затем `Enter`, выйти: `Ctrl+X`.

После изменения перезапустить MAPS:

```bash
sudo systemctl restart maps
sudo systemctl is-active maps   # должно быть: active
```

**На локальном компьютере** — то же самое, но файл `.env` в папке проекта:

```bash
nano /home/dan/dev/projects/python/PythonProject/.env
```

### 14.4 Как сменить секретный ключ `SECRET_KEY`

`SECRET_KEY` используется для подписи сессионных cookie. Если ключ скомпрометирован (например, случайно попал в git) — нужно сгенерировать новый. Все текущие сессии при этом станут недействительными (все пользователи будут автоматически разлогинены).

```bash
# Сгенерировать новый ключ (выполнить на любом компьютере с Python)
python3 -c "import secrets; print(secrets.token_hex(32))"
```

Пример вывода:
```
b0bfdc340f9e7f2f3388a8b68d7f51e5e22eb92623e5fbe8631e9d509d30cb26
```

Скопировать ключ и вставить в `.env` на сервере:

```bash
nano /home/ubuntu/maps/.env
# Найти строку SECRET_KEY=... и заменить на новое значение
```

Перезапустить MAPS:

```bash
sudo systemctl restart maps
```

> **Важно:** `SECRET_KEY` должен быть разным на локальной машине и на сервере. Никогда не коммитьте реальный `SECRET_KEY` в git — он должен быть только в `.env`, который не отслеживается (добавлен в `.gitignore`).

### 14.5 Несколько пользователей

Текущая реализация поддерживает **одного пользователя** (один логин + пароль в `.env`). Это достаточно для команды, которая работает с одним общим аккаунтом.

Если нужны разные учётные записи для разных людей — потребуется доработка кода (добавление таблицы пользователей в БД). Для большинства задач это избыточно — проще дать всей команде один пароль.

**Практические рекомендации для команды:**
- Используйте один общий аккаунт (`admin`) — MAPS не хранит историю действий по пользователям
- Если работает несколько людей одновременно — сессии не конфликтуют, у каждого своя cookie в браузере
- Смените пароль с `CHANGE_ME` на что-то более сложное перед выходом в production

### 14.6 Что делать если забыли пароль

Пароль хранится в открытом виде в `.env` — его можно просто посмотреть:

```bash
# На сервере
ssh -i /home/dan/keys/oracle.pem ubuntu@132.145.232.46
grep MAPS_PASSWORD /home/ubuntu/maps/.env
```

Если `.env` недоступен — просто задайте новый пароль (см. раздел 14.3).

### 14.7 Ошибка «Неверный логин или пароль»

Если не получается войти:

1. **Проверьте пробелы** — в поле логина не должно быть пробелов в начале или конце строки
2. **Проверьте регистр** — `Admin` ≠ `admin`, `MAPS2026` ≠ `CHANGE_ME`
3. **Посмотрите логи сервера** — там видны все попытки входа:
   ```bash
   sudo journalctl -u maps -n 20 --no-pager
   # Ищите строки вида:
   # WARNING — Неудачная попытка входа: логин='admin'
   # INFO    — Успешный вход: admin
   ```
4. **Проверьте переменные в .env:**
   ```bash
   grep -E "MAPS_USERNAME|MAPS_PASSWORD" /home/ubuntu/maps/.env
   ```
5. **Перезапустите MAPS** после изменения `.env` — новые значения читаются при старте:
   ```bash
   sudo systemctl restart maps
   ```

### 15.2 Пакетные сбросы данных

Все команды сброса запрашивают подтверждение. Флаг `--yes` (или `-y`) пропускает запрос.

---

#### `maps reset-data`

**Полный** сброс всех данных. Удаляет содержимое всех 14 таблиц с данными.
Структура таблиц (схема) остаётся.

```bash
maps reset-data
# Спросит подтверждение: "Сброс всех данных БД..."
```

Когда использовать: переход с тестовых данных на реальные (разовая операция).

---

#### `maps reset-works [--yes]`

Удалить работы + потребности + результаты распределения.
Оставляет нетронутыми: материалы, склады, остатки, поставки.

```bash
maps reset-works
maps reset-works --yes      # без запроса подтверждения
maps reset-works -y         # то же самое, сокращённо
```

---

#### `maps reset-requirements [--yes]`

Удалить потребности, списания, «выдано не списано» и результаты распределения.
Работы и материалы остаются.

```bash
maps reset-requirements --yes
```

Когда использовать: начало нового цикла планирования — работы те же, потребности новые.

---

#### `maps reset-stock [--yes]`

Удалить все складские остатки (партии) и справочник складов.

```bash
maps reset-stock --yes
```

Когда использовать: перед загрузкой свежего снимка склада из SAP.

---

#### `maps reset-supplies [--yes]`

Удалить все поставки и строки поставок.

```bash
maps reset-supplies --yes
```

---

#### `maps reset-sessions [--yes]`

Удалить все сессии распределения и их результаты.
Исходные данные (работы, склады, потребности) остаются.

```bash
maps reset-sessions --yes
```

Когда использовать: нужно запустить распределение заново с теми же данными.

---

#### `maps session-delete SESSION_ID [--yes]`

Удалить одну конкретную сессию (и её результаты, движения, дефицит).

```bash
maps session-delete 20260530_143055_a1b2c
maps session-delete 20260530_143055_a1b2c --yes
maps session-delete "июнь_2026_план_А" -y
```

Аргументы:
| Аргумент / флаг | Обязательный | Описание |
|---|---|---|
| `SESSION_ID` | ✅ | ID сессии (из `maps session-list`) |
| `--yes` / `-y` | — | Не спрашивать подтверждение |

### 15.3 Пакетный импорт (из Excel)

Все команды импорта принимают один обязательный аргумент — путь к файлу,
и один необязательный флаг `--sheet` для выбора листа.

---

#### `maps import-works FILE [--sheet]`

Загрузить перечень работ: наименования, даты, филиал, завод, тип, приоритет.
Создаёт работы или обновляет существующие (по коду работы).

```bash
maps import-works data/import/works.xlsx
maps import-works data/import/works.xlsx --sheet "Перечень работ"
maps import-works data/import/works.xlsx -s 1          # второй лист (нумерация с 0)
```

---

#### `maps import-requirements FILE [--sheet]`

Загрузить потребности обычных работ в материалах.
**Сбрасывает** все предыдущие потребности, списания, выданное и результаты — «чистый лист».

```bash
maps import-requirements data/import/requirements.xlsx
maps import-requirements data/import/requirements.xlsx --sheet "Потребности 2026"
```

---

#### `maps import-emergency FILE [--sheet]`

Загрузить аварийные работы с потребностями.
Все работы в этом файле получают `is_emergency=True` и обрабатываются **первыми**.

```bash
maps import-emergency data/import/emergency_requirements.xlsx
maps import-emergency data/import/emergency_requirements.xlsx --sheet 0
```

---

#### `maps import-stock FILE [--sheet]`

Загрузить складские остатки (партии материалов).
Полностью заменяет текущие остатки — логика «снимок на дату».

```bash
maps import-stock data/import/stock.xlsx
maps import-stock /home/ubuntu/data/stock_2026_06.xlsx --sheet "Остатки склада"
```

---

#### `maps import-supplies FILE [--sheet]`

Загрузить поставки (материалы «в пути»).
Привязаны к **филиалу** — работа получает поставки только своего филиала.

```bash
maps import-supplies data/import/supplies.xlsx
maps import-supplies data/import/supplies.xlsx --sheet "Поставки"
```

---

#### `maps import-writeoffs FILE [--sheet]`

Загрузить фактические списания (Слой 1).
Перед использованием должны быть загружены потребности.

```bash
maps import-writeoffs data/import/writeoffs.xlsx
maps import-writeoffs data/import/writeoffs.xlsx -s "Списания"
```

---

#### `maps import-issued FILE [--sheet]`

Загрузить «Выдано не списано» (Слой 2).
Материал уже на объекте, но документ списания не оформлен.

```bash

maps import-issued data/import/issued.xlsx --sheet "Выдано"
```

#### `maps import-transfers FILE [--sheet]`

Загрузить согласованные межфилиальные перемещения (Слой 3в).
Загружается после первого распределения, перед повторным запуском `maps allocate`.

```bash
maps import-transfers data/import/approved_transfers.xlsx
```

### 15.5 Точечное изменение — Работы

---

#### `maps work-add KOD [OPTIONS]`

Добавить новую работу. Код работы должен быть уникальным.

```bash
# Минимальный вариант
maps work-add W-2026-099

# Полный вариант
maps work-add W-2026-001 \
  --nazvanie "Ремонт насоса ЦН-101" \
  --filial "Алматы" \
  --zavod "AL01" \
  --podrazdelenie "Цех №3" \
  --tip "Ремонт" \
  --priority 1 \
  --start 01.06.2026 \
  --end 30.06.2026 \
  --status active

# Аварийная работа
maps work-add AVR-2026-007 \
  --emergency \
  --nazvanie "Авария трубопровода ТП-15" \
  --filial "Шымкент" \
  --start 15.06.2026
```

Все флаги необязательные:

| Флаг | Описание | Пример |
|---|---|---|
| `--nazvanie TEXT` | Наименование работы | `"Ремонт насоса ЦН-101"` |
| `--filial TEXT` | Филиал | `"Алматы"` |
| `--zavod TEXT` | Код завода SAP | `"AL01"` |
| `--podrazdelenie TEXT` | Подразделение | `"Цех №3"` |
| `--tip TEXT` | Тип работы | `"Ремонт"`, `"Монтаж"`, `"ТО"` |
| `--priority N` | Приоритет: 1/2/3 | `1` (высший), `2`, `3` (низший) |
| `--start ДД.ММ.ГГГГ` | Дата начала | `01.06.2026` |
| `--end ДД.ММ.ГГГГ` | Дата окончания | `30.06.2026` |
| `--emergency` | Пометить аварийной | флаг без значения |
| `--status TEXT` | Статус | `active`, `completed`, `cancelled`, `on_hold` |

---

#### `maps work-update KOD [OPTIONS]`

Обновить поля существующей работы. Обновляются **только переданные** флаги.

```bash
# Изменить статус
maps work-update W-2026-001 --status completed

# Изменить приоритет и дату окончания
maps work-update W-2026-001 --priority 1 --end 15.07.2026

# Сделать работу аварийной
maps work-update W-2026-001 --emergency

# Снять признак аварийности
maps work-update W-2026-001 --no-emergency

# Изменить наименование и филиал
maps work-update W-2026-001 --nazvanie "Ремонт насоса ЦН-102 (обновлено)" --filial "Шымкент"
```

Флаги те же что у `work-add` плюс `--no-emergency` (снимает флаг аварийности).

---

#### `maps work-delete KOD [--yes]`

Удалить работу **каскадно**: вместе с потребностями и результатами распределения.
Операция необратима.

```bash
maps work-delete W-2026-001             # спросит подтверждение
maps work-delete W-2026-001 --yes       # без подтверждения
maps work-delete "ПР-АЛ-2026-0042" -y
```

### 15.6 Точечное изменение — Потребности

---

#### `maps req-set KOD SYS_NOMER AMOUNT [--price PRICE]`

Создать или обновить потребность (работа–материал–количество).
Если запись уже существует — обновляет; если нет — создаёт.
При обновлении сбрасывает `raspredeleno` и `deficit` в ноль.

```bash
# Установить потребность 100 единиц без цены
maps req-set W-2026-001 000000000010012345 100,0

# Установить потребность с прогнозной ценой
maps req-set W-2026-001 000000000010012345 250,500 --price 1500,75
maps req-set W-2026-001 000000000010012345 250,500 -p 1500,75
```

Аргументы:

| Аргумент | Обязательный | Описание |
|---|---|---|
| `KOD` | ✅ | Код работы (должна существовать в БД) |
| `SYS_NOMER` | ✅ | 18-значный системный номер материала |
| `AMOUNT` | ✅ | Количество (запятая как разделитель: `100,5`) |
| `--price` / `-p` | — | Прогнозная цена (запятая: `1500,75`) |

---

#### `maps req-delete KOD SYS_NOMER [--yes]`

Удалить одну потребность (строку requirements).

```bash
maps req-delete W-2026-001 000000000010012345
maps req-delete W-2026-001 000000000010012345 --yes
maps req-delete W-2026-001 000000000010012345 -y
```

### 15.8 Точечное изменение — Склады и остатки

---

#### `maps warehouse-add KOD --filial FILIAL --zavod ZAVOD [--tip TIP]`

Добавить склад в справочник. Код должен быть уникальным.

```bash
# Минимальный вариант (filial и zavod — обязательные)

# С типом склада
maps warehouse-add SHY-002 --filial "Шымкент" --zavod "SH01" --tip "Центральный"

```

| Флаг | Обязательный | Описание |
|---|---|---|
| `--filial` / `-f` | ✅ | Филиал (должен совпадать с work.filial) |
| `--zavod` / `-z` | ✅ | Код завода SAP Plant |
| `--tip` / `-t` | — | Тип: `Центральный`, `Цеховой`, `Временный` |

---

#### `maps stock-add WAREHOUSE SYS_NOMER AMOUNT PRICE [--date DATE] [--batch TEXT]`

Добавить **новую партию** материала на склад. Каждый вызов создаёт новую строку.
Для замены всех остатков используйте `maps import-stock`.

```bash
# Минимальный вариант
maps stock-add SLT-001 000000000010012345 500,0 1250,50

# С датой поступления (важно для FIFO-сортировки!)
maps stock-add SLT-001 000000000010012345 500,0 1250,50 --date 01.05.2026

# С номером партии и датой
maps stock-add SLT-001 000000000010012345 100,0 1300,00 \
  --batch "4500123456" \
  --date 15.05.2026
```

| Аргумент / флаг | Обязательный | Описание |
|---|---|---|
| `WAREHOUSE` | ✅ | Код склада (должен существовать в БД) |
| `SYS_NOMER` | ✅ | Системный номер материала |
| `AMOUNT` | ✅ | Количество (запятая: `500,0`) |
| `PRICE` | ✅ | Стоимость за единицу (запятая: `1250,50`) |
| `--date` / `-d` | — | Дата поступления `ДД.ММ.ГГГГ` (влияет на FIFO) |
| `--batch` / `-b` | — | Номер партии (информативно) |

---

#### `maps stock-delete WAREHOUSE SYS_NOMER [--yes]`

Удалить **все партии** указанного материала с конкретного склада.

```bash
maps stock-delete SLT-001 000000000010012345
maps stock-delete SLT-001 000000000010012345 --yes
maps stock-delete SHY-002 000000000010098765 -y
```

### 15.12 Настройки и сервер

---

#### `maps set-year YEAR`

Установить год планирования.
Работы, дата окончания которых раньше 1 января этого года, считаются завершёнными
и не участвуют в распределении.

```bash
maps set-year 2026
maps set-year 2027
```

---

#### `maps settings-show`

Показать текущий год планирования и время последнего обновления.

```bash
maps settings-show
```

---

#### `maps serve [--host HOST] [--port PORT] [--reload]`

Запустить FastAPI-сервер с дашбордом.

```bash
# По умолчанию: 0.0.0.0:8000
maps serve

# На другом порту
maps serve --port 9000
maps serve -p 9000

# Только локальный доступ (заблокировать доступ из сети)
maps serve --host 127.0.0.1

# Режим разработки — перезапуск при изменении кода
maps serve --reload
maps serve --port 8080 --reload
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--host` / `-h` | `0.0.0.0` | Адрес прослушивания. `0.0.0.0` = все интерфейсы |
| `--port` / `-p` | `8000` | TCP-порт |
| `--reload` | выкл | Автоперезапуск при изменении кода (только для разработки) |
